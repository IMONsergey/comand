Он создаёт проверенный снимок всех аккаунтов в `~/.comand/verified-backups` и запускает из временной копии отдельный loopback hub для проверки восстановления. Первый ручной запуск службы завершился успешно; восстановлены аккаунт, устройства, проекты, задачи и OAuth. Служебные утилиты установлены в `~/.local/share/comand-ops`, их `dist` указывает на проверенный установленный выпуск. При обновлении приложения эту ссылку нужно переключить на совместимый новый выпуск.

Это локальное резервирование сервера, не копия состояния агентов и не защита от потери диска. Для восстановления после потери сервера нужен отдельный защищённый внешний backup. Старые снимки автоматически не удаляются; контролируйте свободное место.

## Откат

Не восстанавливайте старую базу поверх новых пользовательских данных после начала работы пользователей. Сначала остановите новые задачи и сохраните свежую копию всего состояния. Для отката только кода верните прежние определения двух служб из backup, выполните `systemctl --user daemon-reload` и запустите службы. Предыдущие каталоги программы сохранены. При необходимости отката схемы восстановите согласованный полный backup отдельно, после проверки потери изменений со времени копирования.

Для systemd user в административной сессии используются `XDG_RUNTIME_DIR=/run/user/1000` и `DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/1000/bus`. Настройки Nginx, сертификатов и других приложений в этот выпуск не изменялись.

Проверки кода и ограничения: [VERIFICATION.md](VERIFICATION.md). Инструкция партнёру: [INSTALL.md](INSTALL.md).
