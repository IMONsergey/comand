## Сохранность данных

Перед переключением проверено отсутствие незавершённых задач во всех рабочих средах, остановлены только службы Comand, сохранены полный каталог hub, состояние Linux-агента и определения служб. Последняя резервная копия:

```text
/home/sergey/.comand/backups/before-0.2.1-20261031T051339Z
```

Дополнительно включён `comand-hub-backup.timer`: ежедневно около 06:30 МСК (03:30 UTC, задержка до минуты). Он создаёт проверенный снимок всех аккаунтов в `~/.comand/verified-backups` и запускает из временной копии отдельный loopback hub для проверки восстановления. Первый ручной запуск службы завершился успешно; восстановлены аккаунт, устройства, проекты, задачи и OAuth. Служебные утилиты установлены в `~/.local/share/comand-ops`, их `dist` указывает на проверенный установленный выпуск. При обновлении приложения эту ссылку нужно переключить на совместимый новый выпуск.

Это локальное резервирование сервера, не копия состояния агентов и не защита от потери диска. Для восстановления после потери сервера нужен отдельный защищённый внешний backup. Старые снимки автоматически не удаляются; контролируйте свободное место.

Прежняя локальная рабочая среда Mac сохранена. Агент 0.2.1 на Mac проверен отдельной временной службой, включая установку без Node.js; постоянный Mac-агент пока не перенесён в публичный hub. Новая регистрация создаёт изолированную среду и автоматически не присваивает старые устройства или историю. Старый владелец может войти своим прежним токеном. Объединение с уже созданным аккаунтом требует отдельного явного переноса.

## Откат

Не восстанавливайте старую базу поверх новых пользовательских данных после начала работы пользователей. Сначала остановите новые задачи и сохраните свежую копию всего состояния. Для отката только кода верните прежние определения двух служб из backup, выполните `systemctl --user daemon-reload` и запустите службы. Предыдущие каталоги программы сохранены. При необходимости отката схемы восстановите согласованный полный backup отдельно, после проверки потери изменений со времени копирования.

Для systemd user в административной сессии используются `XDG_RUNTIME_DIR=/run/user/1000` и `DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/1000/bus`. Настройки Nginx, сертификатов и других приложений в этот выпуск не изменялись.
