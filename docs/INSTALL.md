# Установка агента Comand

Агент подключает ваш Mac или Linux-компьютер к серверу Comand. Поддерживаются macOS Intel/Apple Silicon и Linux x64/arm64 с glibc. Windows и Alpine/musl этим установщиком не поддерживаются. Нужны `bash`, `curl`, `tar`, `gzip` и `shasum` либо `sha256sum`; Git, npm и сборка исходников не нужны.

## Подключение

1. Войдите в свою учётную запись Comand. При регистрации сохраните показанный код восстановления: отправка писем и восстановление через почту не настроены.
2. Откройте **Устройства → Подключить устройство**. Укажите имя, существующую рабочую папку и нужные разрешения. Создайте одноразовый код и скопируйте команду установки.
3. Выполните команду в терминале подключаемого компьютера **без sudo**. После запуска службы устройство появится в вашей панели. Создайте проект с папкой внутри разрешённых границ.

Пример той же команды; замените адрес, код и имя своими значениями:

```bash
mkdir -p "$HOME/Projects/comand-workspace"
installer="$(mktemp)"
curl --fail --silent --show-error --proto '=https' \
  https://comand.example.com/install.sh --output "$installer" &&
bash "$installer" \
  --url https://comand.example.com \
  --code YOUR_ONE_TIME_CODE \
  --name "Мой Mac" \
  --root "$HOME/Projects/comand-workspace" \
  --data-dir "$HOME/.comand/agent" \
  --allow-shell
rm -f "$installer"
```

Код действует 10 минут и используется один раз. Не публикуйте выданную команду. Установщик отключает трассировку до чтения параметров; сама вставленная команда может остаться в истории терминала. Несколько папок задаются повторением `--root`. Удалённый сервер должен иметь HTTPS-адрес без пути; HTTP разрешён только для `localhost`, `127.0.0.1` и `[::1]` при локальной проверке.

Установщик проверяет SHA-256 архива, размещает программу в `~/.local/share/comand` и сохраняет настройки, ключ устройства и доказательства исполнения отдельно в `~/.comand/agent`. Папки имеют права `0700`, ключ — `0600`. Если Node.js 24 уже есть, используется он; иначе скачивается отдельный Node.js 24.22.1 с `nodejs.org` и проверяется по официальному `SHASUMS256.txt`. Системный Node не заменяется. Контрольная сумма обнаруживает повреждение; доверие к выпуску основано на HTTPS-сервере, с которого загружены установщик и архив.

На Mac запускается пользовательская служба launchd, на Linux — systemd user. Для другой папки программы используйте `--install-dir /absolute/path`; она должна быть отдельной и пустой при первой установке. Node.js не поддерживает обратную косую черту (`\`) в пути программы; пробелы и кавычки допустимы. Программа и состояние не могут находиться друг внутри друга. Для ручного запуска добавьте `--no-service`, затем выполните:

```bash
"$HOME/.local/share/comand/bin/comand" agent run --data-dir "$HOME/.comand/agent"
```

`--allow-shell` разрешает команды с правами вашего пользователя ОС. Разрешённые папки ограничивают файловые операции, но не произвольные команды терминала. Для изоляции используйте отдельную учётную запись или виртуальную машину.

## Браузер

`--allow-browser` разрешает просмотр страницы и снимок в отдельном временном профиле. Личные вкладки и авторизация не используются. Агент может использовать установленный Google Chrome. Если браузера нет, установите Chromium:

```bash
"$HOME/.local/share/comand/node" \
  "$HOME/.local/share/comand/current/node_modules/playwright/cli.js" install chromium
```

На Linux браузеру могут понадобиться системные библиотеки; сообщение Playwright укажет недостающие пакеты. Установщик Comand не устанавливает системные пакеты и не запрашивает sudo. Node/Python REPL и другие долгоживущие процессы поддерживаются через потоки ввода/вывода; полноценного PTY нет. Управление нативными окнами, личным браузером и редакторы документов/Figma в эту версию не входят. Подробнее: [процессы](PROCESSES.md).

## Обновление

Завершите активные задачи и сохраните резервную копию папки состояния. Загрузите свежий `/install.sh` с того же сервера и выполните:

```bash
installer="$(mktemp)"
curl --fail --silent --show-error --proto '=https' \
  https://comand.example.com/install.sh --output "$installer" &&
bash "$installer" --update --url https://comand.example.com \
  --data-dir "$HOME/.comand/agent"
rm -f "$installer"
```

Если при установке меняли `--install-dir`, передайте тот же путь. Код подключения, имя, папки и разрешения при обновлении не передавайте: они сохраняются. Повторная установка с кодом в уже подключённую папку отклоняется до загрузки архива. Для другого устройства/аккаунта используйте другую папку состояния и новый код.

Обновление переключает программу на проверенный выпуск и перезапускает службу. Старые выпуски остаются на диске: они могут быть нужны уже принятым задачам. При ошибке запуска службы установщик пытается вернуть предыдущую версию. Ключ и история не удаляются, принятые задачи автоматически не повторяются. Проверьте состояние службы после любой ошибки обновления.

## Состояние и удаление

```bash
"$HOME/.local/share/comand/bin/comand" service status --kind agent \
  --data-dir "$HOME/.comand/agent"
"$HOME/.local/share/comand/bin/comand" agent status --data-dir "$HOME/.comand/agent"
```

Чтобы отключить автозапуск:

```bash
"$HOME/.local/share/comand/bin/comand" service uninstall --kind agent \
  --data-dir "$HOME/.comand/agent"
```

Команда сохраняет данные. После завершения всех задач и удаления служб, использующих эту установку, папку `~/.local/share/comand` можно удалить. Для полного отключения от сервера отзовите устройство в панели. Папку `~/.comand/agent` удаляйте отдельно только после сохранения нужной истории и проверки незавершённых задач. Отзыв доступа или остановка агента не останавливает автоматически уже принятые процессы.

## Если установка не удалась

| Сообщение или симптом | Что проверить |
| --- | --- |
| «Установщик пока недоступен», HTTP 503 | Администратор ещё не опубликовал архив на этом сервере. |
| Контрольная сумма не совпала | Повторите загрузку. При повторной ошибке администратор должен опубликовать архив и checksum одним выпуском. Не отключайте проверку. |
| Код истёк или уже использован | Создайте новый код в панели. Если `config.json` уже появился, используйте `--update`, чтобы завершить установку без повторного подключения. |
| Агент уже подключён | Используйте `--update`; не заменяйте `config.json` вручную. |
| systemd user недоступен | Выполните команду в обычной пользовательской сессии. Для ручного режима используйте `--update --no-service`. Работа после выхода пользователя требует настройки linger администратором. |
| launchd не запускает службу | Войдите в обычную GUI-сессию macOS, затем повторите `--update`. При необходимости используйте ручной режим. |
| Осталась `.install-lock` | Убедитесь, что другой установщик не работает. Удалите только пустую `.install-lock` из папки программы/состояния и повторите команду. |
| Устройство offline | Компьютер должен быть включён, не спать и иметь доступ к HTTPS-серверу. Проверьте `service status`, затем `service.stderr.log` в папке состояния; не публикуйте журнал без проверки содержимого. |

## Для администратора выпуска

В проверенном checkout с Node.js 24 и согласованными версиями в `package.json`, lockfile и протоколе:

```bash
npm ci
npm run verify
node scripts/build-release.mjs --out /absolute/path/to/new-release-directory
```

Скрипт устанавливает production-зависимости по lockfile в отдельную временную папку (`npm ci --omit=dev --ignore-scripts`), добавляет готовый `dist`, манифест и создаёт `comand-agent-VERSION.tar.gz`, его `.sha256`, фиксированные имена `comand-agent.tar.gz[.sha256]` и `install.sh`. Архив не содержит исходный checkout, состояние, ключи или скачанный браузер. Одинаковые входные файлы, версии Node/zlib и lockfile дают одинаковый SHA-256; даты, владельцы и порядок файлов нормализованы. `--offline` требует уже заполненного npm cache.

Подключите `installDistribution(app, { directory: '/absolute/path/to/release-directory' })` до маршрута SPA. По умолчанию используется `releases` рядом с `dist`. Модуль публикует только `/install.sh`, `/downloads/comand-agent.tar.gz` и `/downloads/comand-agent.tar.gz.sha256`; каталог и произвольные файлы недоступны. Публикуйте готовую папку целиком атомарным переключением; не собирайте её поверх обслуживаемого выпуска. Версионные файлы храните для сверки/отката. SHA-256 и версию развёрнутого выпуска фиксируйте в журнале развёртывания.

Автоматические тесты проверяют реальные загрузку/распаковку, аргументы с пробелами и shell-символами, отказ при неверной сумме/пути архива, сохранение ключа и откат программы при ошибке службы. Эти тесты используют имитацию service CLI; они не заменяют проверку launchd/systemd и Node bootstrap на целевых устройствах. Подтверждённые проверки конкретного выпуска перечисляются в [VERIFICATION.md](VERIFICATION.md).

Для проверки готового архива с настоящим launchd/systemd запустите в обычной пользовательской сессии:

```bash
node scripts/native-smoke.mjs --release-dir /absolute/path/to/release-directory
```

Скрипт создаёт отдельный временный сервер, подключает агента через установщик, проверяет PID службы и результат команды `printf`, затем удаляет только свою службу и временные данные. Существующие службы не меняются. Если остановку или завершение задачи подтвердить не удалось, временные данные сохраняются, а их путь возвращается в JSON. Для этой проверки используется уже установленный Node.js 24; загрузку Node при его отсутствии проверяют отдельно.
