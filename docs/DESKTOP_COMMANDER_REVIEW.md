# Что Comand перенимает у Desktop Commander

Проверка 31 октября 2026. Источник: [официальный репозиторий DesktopCommanderMCP](https://github.com/wonderwhy-er/DesktopCommanderMCP/tree/9a171d1dae74de94bf07e6e13878006fb69fa600), ревизия `9a171d1dae74de94bf07e6e13878006fb69fa600`, и описания 29 инструментов подключённого Remote Desktop Commander.

Изучены все шесть публичных инструкций для агентов: `desktop-commander-overview`, `terminal`, `knowledge-base`, `obsidian-vault`, `ai-tools-setup`, `computer-health-check`; их шесть справочных файлов; правило `desktop-commander-default.mdc`; FAQ, политика безопасности, инструкции Remote Device и установщиков. Копии skills для Claude/Cursor сравнены: различаются только оформление ссылок в двух файлах. В README проверены возможности, установка, удалённое подключение и работа инструментов. Это обзор опубликованных инструкций и доступного контракта, а не аудит закрытого сервиса Desktop Commander.

## Основная ошибка прежнего сценария

Для работы с уже существующим проектом Comand требовал сначала вручную добавить проект. Если путь не был известен, возникало искушение создать пустую рабочую папку ради доступа к инструментам. Подключение компьютера и поиск проекта должны работать независимо от наличия такой записи.

В 0.3 добавлен порядок: выбрать устройство → проверить уже добавленные проекты → найти папку на устройстве → использовать её → прочитать инструкции проекта → выполнять задачу. Регистрация папки в панели не создаёт файлы, клон репозитория или отдельную среду. Новые файлы нужны только для действительно новой работы после проверки существующих вариантов.
В 0.4 эта последовательность выполняется агентом через `prepare_project`: пользователь подключает компьютер и описывает задачу. Ручная регистрация проекта больше не является шагом начала работы. Новые подключения дают файловый доступ `/` с правами пользователя ОС; прежние ограниченные профили не расширяются обычным обновлением. При полном доступе первый проход поиска начинается с домашней папки и обозначается частичным; дальнейший путь агент уточняет сам без нового разрешения Comand.

## Принципы и реализация

| Принцип                                              | Что сделано в Comand 0.3                                                                                    |
| ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Работать на нужном реальном устройстве               | `list_devices`, явный `deviceId`, явный выбор устройства в поиске, если подключено несколько компьютеров    |
| Сначала найти существующую работу                    | `list_projects` с фильтром; `find_projects` без `projectId`; `open_project` повторно использует тот же путь |
| Не путать отсутствие результата с отсутствием файлов | Видимая область поиска, предупреждения и признак неполного обхода; уточнение пути                           |
| Сохранять контекст                                   | `project_context`, заметки и история задач; инструкция читать README/AGENTS перед изменениями               |
| Различать файлы, процессы и подключение              | Отдельные инструменты для файлов и управления собственными процессами                                       |
| Повторно использовать интерактивный процесс          | Постоянные сессии stdin/stdout; независимые запуски не разделяют переменные                                 |
| Читать результат постепенно                          | Ограниченные чтения и журналы с `nextOffset`                                                                |
| Не повторять действие из-за задержки ответа          | ID задачи, ключ намерения, явная неопределённость; принятые команды не запускаются автоматически повторно   |
| Сохранять чужие изменения                            | Запись с `expectedHash` или `createOnly`                                                                    |
| Учитывать реальную модель доступа                    | Папки ограничивают файловые операции; shell работает с правами пользователя ОС                              |

Инструкции передаются MCP-клиенту при инициализации из `src/mcp/instructions.ts`. Тест с официальным MCP SDK проверяет, что клиент их получает. Продукт не может гарантировать следование инструкциям каждой сторонней моделью; проверки аккаунта, устройства, пути и прав выполняет сервер/агент.

## Ограничения поиска

Поиск читает названия и типы записей каталогов, а не содержимое файлов. Маркеры проекта включают `.git`, `package.json`, `pyproject.toml`, `Cargo.toml`, `go.mod`, `index.html`, README и другие распространённые файлы. Это кандидаты, а не доказательство назначения проекта: несколько копий нужно различить по пути и контексту.

Поиск ограничен выданными локально папками, 4 секундами, глубиной 4, 2500 каталогами, 25000 записями и 100 результатами. Скрытые папки, зависимости, сборки и символические ссылки пропускаются. Устройство может быть недоступно; такой запрос истекает через 120 секунд. Успешный результат можно выбрать в течение 10 минут. Поиск требует агента 0.3; старые агенты продолжают выполнять прежние задачи.

## Что ещё не равно Desktop Commander

| Возможность                                                      | Состояние Comand                                                                                           |
| ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Потоковый поиск по имени/содержимому с продолжением и остановкой | Есть ограниченный поиск проектов и буквальный поиск текста; универсальной потоковой сессии поиска пока нет |
| `edit_block` с точной проверкой количества замен                 | Есть условная атомарная запись; отдельного инструмента точечной замены пока нет                            |
| XLSX, DOCX, PDF как отдельные форматы инструментов               | Не реализовано                                                                                             |
| Все процессы ОС и остановка произвольного PID                    | Управляются собственные сессии Comand                                                                      |
| Windows                                                          | Установщик поддерживает только macOS/Linux                                                                 |
| Полноценный PTY                                                  | Есть потоки stdin/stdout; программы, которым нужен TTY, не поддерживаются                                  |
| Нативные окна и личный авторизованный браузер                    | Не реализовано; проверка страницы использует отдельный профиль                                             |

FAQ Desktop Commander местами противоречит более свежей политике безопасности и текущим названиям инструментов. Поэтому утверждения о полной изоляции, обязательных подписках и старые имена команд не переносились. Comand не объявляется полной заменой Desktop Commander до проверки оставшихся возможностей.
